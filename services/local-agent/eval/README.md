# P0 量化评测基线

对应《算法设计说明书 V1.0》第 8 节（三方案生成与择优）与第 12 节（偏好记忆与推荐）。
本目录同时覆盖决策算法与产品闭环。生成的基线文件不要手改：决策场景定义在
`../scripts/eval-decision.mjs`，20 件产品任务定义在 `tasks.json`，错误集定义在
`error-cases.json`，自动化测试位于 `../test/`。

## 运行

```bash
cd services/local-agent
npm run eval:decision   # 重新生成本目录三个文件，边界断言失败时 exit 1
npm run eval:product    # 运行 20 件真实 Python 任务并生成产品基线，门槛失败时 exit 1
npm test                # 含 test/decision.test.js（权重/相似度/MMR/偏好/生产接线）
npm run test:capacity:heavy # 显式执行 50MB/100 万行容量测试
```

## 产品验收门槛

- 20 个标准任务完成率 ≥ 85%，首次执行成功率 ≥ 70%，最多 3 次修复后成功率 ≥ 90%。
- 代码与 ChartSpec 往返一致率 ≥ 95%，每种核心图型至少 3 个数据集。
- 连续 5 轮样式反馈保持上下文正确；首预览 P95 ≤ 60 秒，重渲染 P95 ≤ 3 秒。
- 错误集分类命中率 100%。普通 `npm test` 覆盖约 10MB 数据；50MB/100 万行测试因资源消耗需显式运行。

## 场景（均为小型可解释合成数据）

1. `01_trend_long`：8 观测点 × 2 系列，趋势场景。
2. `02_group_comparison`：3 观测点 × 4 系列（含 sd），组间比较场景。
3. `03_high_density`：6 × 4 = 24 数据点，高密度场景。
4. `04_duplicate_candidates`：同 id 重复候选 + 近似重复折线，验证去重与 MMR 边际惩罚。
5. `05a_infeasible_eliminated` / `05b_too_few_feasible` / `05c_no_valid_candidate`：不可执行候选淘汰、可执行不足 3、无有效候选。
6. `06_extreme_preference__default/__extreme`：PreferenceFit 极端化前后的首选切换。

外加 λ ∈ {0, 0.25, 0.5, 0.75, 1} 敏感性扫描，以及 k/λ/权重/子分/严格候选数的 8 项边界校验。

## 基线指标口径

- **入选效用**：入选方案 U(c) 的和与最小值（越高越好）。
- **两两相似度**：入选方案对的六维加权 Sim（均值/最大值；越低越多样）。
- **差异维度数**：每对入选方案不同的设计维度数（说明书要求任意两套 ≥ 2）。
- **不可执行淘汰**：被 8.4“无法验证不得入选”规则剔除的候选数及原因。
- **选择稳定性**：候选洗牌 50 次后入选集合不变的比例（确定性 tie-break，期望 1）。
- **本地运行成本**：仅测量候选池构建与 MMR 的毫秒耗时（纯本地、零依赖）；**不含商业定价**，仓库没有价格表。

## 当前 P0 基线（以最近一次运行为准，详见 JSON 的 `p0` 与 `findings`）

1. 生产候选池 K=8 且 8 个候选均可执行，覆盖柱图、折线、散点、相关性热力图、1×2/2×1/2×2 复合布局。
2. 数据形态会改变候选效用与入选图型；矩阵型数据提升热力图/2×2，长趋势提升折线/散点。
3. 可执行候选少于 3 个时，生产严格模式抛 `INSUFFICIENT_CANDIDATES`；诊断场景仍可用 `strict:false` 输出 warning 与部分选择。
4. 缺失数值通过真实 CSV 接入与确定性统计检查，保持为 `null`，不再用 0 伪造观测。
5. λ=0 时高效用近似重复候选可能同时入选，说明多样性仍依赖 λ 边际项（默认 0.5 为初始配置，非训练所得）。
